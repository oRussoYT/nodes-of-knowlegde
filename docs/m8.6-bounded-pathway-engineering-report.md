## 2. Exact scope implemented

C6 bounded pathway, **heterogeneous multi-entity graph** and **`?pathwayTo` target
selection** (both ratified with the product owner). For a focal person and a
selected target entity (person/organization/contribution/event), the shortest
documented chain of ≥ 2 explicit-assertion steps, bounded to hop cap 4, read inline
on the person page.

## 3. Historical question answered

"What documented chain of explicit records links this person to the entity I
chose, through intermediaries — and exactly which steps compose it?"

## 4. Deterministic rule

A bounded (hop cap 4), cycle-safe traversal over the undirected heterogeneous edge
set; the single minimal-length chain (≥ 2 steps) chosen by (depth, neutral path
key), never by any metric. Each step decomposes to its canonical row with both
endpoint ProjectedNodes in traversal order, the connecting assertion's
category/label, temporal, and provenance.

## 5. Canonical source assertions

`relationships`, `organization_relationships`, `participations`,
`person_contributions`, `organization_contributions`, `person_events`,
`organization_events`, `contribution_events` (+ their kind/capacity vocabularies and
the entity tables for node projection). No new table, no write.

## 7. Database / security audit

Two additive functions; no table/column/RLS/write. `reveal_person_pathway`:
`SECURITY DEFINER`, `search_path` pinned, `auth.uid()` required in-body, revoked from
`PUBLIC`, granted to `authenticated`. The internal `pathway_entity_node` helper is
`STABLE`, `search_path` pinned, and **revoked from PUBLIC with no client grant** —
it is only ever called from within the SECURITY DEFINER function (running as the
definer). Merged people are excluded from every person-endpoint join and from target
resolution; a merged/nonexistent focal → null. Every referenced column was verified
against the live schema during development.

## 8. Projection / parser contract audit

Every projected node (focal, target, and each step endpoint) is emitted in the
canonical `ProjectedNode` shape via the internal helper; pgTAP locks it. The parser
(`parse-pathway.ts`) reuses `parseAnyNode`/`parseTemporal`/provenance and is
fail-closed with a pathway-specific **chain-integrity guarantee**: a document is
shown as a pathway only if every step parses, the declared count matches, the chain
is ≥ 2 steps, and it is **contiguous** (each step's `to` is the next step's `from`,
the first `from` is the focal id, the last `to` is the target id). Any break
degrades to an honest `found:false` — a broken or partial chain is never shown.

## 9. The endpoint rule (the milestone's core discipline)

Enforced end to end: the read model returns only the literal chain and its length;
`describePathwaySummary` states "a documented chain of N steps connects A and B" and
the copy test asserts the text never contains "is connected to"/"are connected" and
carries no closeness/strength/rank/importance/centrality vocabulary; the limits copy
states the chain "is not a connection between its endpoints" and is "never ordered or
scored by length." The hop bound is small (4) and pgTAP proves it (5-step line →
absent). A no-chain result reads "no documented chain within four steps," never "not
connected."

## 10. Constitutional audit (M8 §9.1)

Read-only; no inference/similarity/statistics/prediction/embedding (a chain is a
composition of explicit edges, decomposable link by link); **no metric/rank** (length
is a fact; single minimal chain by neutral key; pgTAP + copy tests); deterministic +
**bounded** (hop cap, cycle-safe simple paths; pgTAP bound + determinism);
decomposable (every step → its canonical row; both endpoints doorways); **endpoint
rule** (never a connection between ends); heterogeneous but never a generic graph
store (composed in bounded SQL over canonical tables; projection shape in TypeScript);
temporally honest (each step's own dates); fail-closed security; honest incompleteness
(four non-collapsed states; ≥ 2-step rule; "not connected" never asserted); no new
destination (inline; no console; nav unchanged); no interpretation (structural
category/label; meaning left to the reader and M9).

## 11. Rejected alternatives

- **Person-only graph.** Rejected in favour of the ratified heterogeneous graph
  (people/institutions/contributions/events).
- **Enumerating all chains / a "reachable people" list.** Rejected: it strains the
  endpoint rule and reads as recommendation. A single minimal chain is returned.
- **Ordering/labelling the chain as "shortest"/"closest"/"strongest".** Rejected as
  ranking (Spec §4); length is stated as a fact only.
- **Including a 1-step chain.** Rejected: a direct link is M7's connection, not a
  pathway (≥ 2-step rule), avoiding overlap.
- **An in-page target picker / discovery console.** Rejected: revelation has no
  destination of its own; the target is set by `?pathwayTo` from an existing doorway.
- **Bare event-link steps without provenance.** Resolved by carrying the event
  record's provenance for event-association steps, keeping every step decomposable.

## 13. Defects found and fixed

Two, caught during sandbox development before delivery: (a) the undirected-edge
construction initially mis-swapped the reversed edge's traversal endpoints — fixed so
each reversed step re-labels its from/to and the chain always reads in traversal
order (verified: A→X→B→C reads correctly); (b) the symmetric-relationship fixtures
violated the `relationships_symmetric_canonical` constraint (source < target) — fixed
in the pgTAP fixtures (canonical ordering) and the e2e spec (a directional kind, which
carries no canonical-ordering constraint, so random fixture ids are safe). No
production logic defect otherwise.

## 14. Validation strategy

The hardest part — the heterogeneous bounded traversal — was validated *first* in a
real Postgres before any TypeScript was written, which de-risked the whole slice. The
pure-logic layer (parser contiguity, derive states, endpoint-rule copy) runs here; the
DB layer is formalised in pgTAP (mirroring the validated sandbox fixtures); the surface
is covered by Playwright. The Mac runs the DB/build/e2e layers.

## 15. Limitations

Hop bound 4 (a chain needing five or more steps reads as an honest absence — bounded
and constitutional, not a silent cut). One minimal chain is shown (others may exist;
stated in the limits) to keep the result bounded and un-ranked. The heterogeneous
traversal is bounded by the hop cap and the simple-path (cycle) guard; on very dense
production hubs the traversal cost should be observed via query plans on the Mac
(Blueprint composition-cost risk) and the cap lowered if needed. Event-association
steps carry the event record's provenance (the bare link has none).
