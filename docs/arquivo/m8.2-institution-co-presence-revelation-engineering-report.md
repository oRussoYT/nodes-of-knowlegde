## 2. Exact scope implemented

Institution-surface co-presence: for a focal institution, the *documented co-presence*
among its participants — for each participant with at least one temporally-overlapping
co-participant, the anchor (person doorway + all of their own participations here) and
the co-present others (person doorway + capacity/temporal/provenance + the
`participations` source establishing the overlap), read inline on
`/institutions/[organizationId]` after the Participation/Contributions engines.

## 3. Historical question answered

"Who does the record document as present at this institution at the same time as
whom?" — the institution-vantage of the M8.1 person question.

## 4. Deterministic rule

Among **dated, non-merged** participations at the focal institution, two people are
co-present iff a participation of each overlaps by the interval test
`a.start ≤ coalesce(b.end,∞) AND b.start ≤ coalesce(a.end,∞)` — **pairwise**, the exact
M8.1 rule (no windows, no clustering). Each person is represented by their earliest
overlapping participation; anchors ordered by `display_name` then id, co-present by
`display_name` then id. Undated (`date_is_unknown`) excluded; merged people excluded;
different-institution excluded by construction.

## 5. Canonical source assertions

`participations` (the composed Assertion), joined to `people` (display_name,
verification_status), `organizations` (name, short_name, verification_status), and
`participation_capacities` (key, label) for projection/labels only. No new source of
truth; no write.

## 7. Database / security audit

Single additive function; no table/column/RLS/write (git diff confirms). `SECURITY
DEFINER`, `set search_path = public, pg_temp`, `auth.uid()` required in-body (raises
otherwise), `revoke all … from public`, `grant execute … to authenticated` —
identical to `reveal_person_cohorts`. Focal institution null when nonexistent;
organizations carry no `merged` verification state (M6.5 check constraint) so there is
no merged-institution case; merged participants excluded (`person.verification_status
<> 'merged'`). Every column referenced (`participations` person_id/organization_id/
capacity/eight temporal columns/source_type/verification_status/id; `people`
display_name/verification_status; `organizations` name/short_name/verification_status;
`participation_capacities` key/label) matches the M6.3/M6.5 schema verified during M8.1.

## 8. Projection / parser contract audit

Every projected node is emitted in the canonical `ProjectedNode` shape
(`type`,`id`,`label`,`secondary_label`,`href`,`verification_status`) — the M8.1
defect (missing `type`, wrong keys) is not reproduced, and the pgTAP **locks** it
(assertions 19–22: organization `type`/`label`, anchor `type`, co-present `type`). The
parser (`parse-organization.ts`) reuses the shared `parseNode`/`parseAnchor`/`parseMember`
primitives, is fail-closed (drops malformed co-present/anchor, rejects mistyped nodes,
never invents), and Vitest confirms the SQL→parser shape via realistic fixtures.

## 9. Temporal / provenance audit

Overlap uses stored dates with open ends coalesced to `infinity`; each person shows
their **own** period (no fabricated overlap window); undated excluded. The anchor
carries **all** of their participations here, so both sides of every overlap are
decomposable. Every co-present person carries its `participations` `source` id and the
full provenance envelope (`source_type`, `verification_status`), rendered through the
shared `ProvenanceAffordance`; provenance is never collapsed to a single confidence.

## 12. Defects found and fixed

**One, found in the validation pass and fixed.** The read model's anchor person node
referenced `ap.person_verification_status`, but the anchor subquery selected only
`(person_id, person_display_name)` from `part` — a scope error that would have failed
`supabase:reset`/`supabase:test` outright (the function would not create/execute:
"column ap.person_verification_status does not exist"). Fixed by adding
`person_verification_status` to that `distinct` select; the projected node shape and all
other logic are unchanged. Caught by static self-review (the DB layer cannot run in the
cloud session), so it is corrected before the Mac run rather than surfacing there.

The M8.1 parse refactor was verified regression-free (M8.1's 19 pure-logic tests pass
unchanged against the harvested primitives), and the full pure-logic suite is 35/35.

## 13. Constitutional audit (M8 §9.1)

Read-only (function only); no inference (overlap + shared institution required —
pgTAP: non-overlap, undated, different-institution excluded); no metric/ranking/
centrality/clustering (neutral ordering; pairwise only, no windows; copy scanned for
banned vocabulary); deterministic (pgTAP: equal calls equal); decomposable (every
co-present → its `participations` row; anchor carries all participations);
temporally honest (own periods, infinity open end, undated excluded); fail-closed
security (SECURITY DEFINER, auth-in-body, revoked/ granted, merged excluded); honest
incompleteness (limits + empty state); no new destination (inline; nav unchanged); no
interpretation (structural "documented co-presence", never "generation"/community/
school/collaboration — copy unit-tested to exclude them).

## 14. Limitations and deferred capabilities

- **Event company (C1 on events)** — deferred: no event reading surface; M8 creates
  none. Awaits an event surface.
- **Comparison (C5)** — deferred to M8.3: "not a standalone page"; its host is the
  M8.3 lineage juxtaposition.
- **Representative-participation overlap.** A person is represented by their earliest
  overlapping participation; consistent with M8.1 and deterministic. Co-presence is
  determined by any dated stint overlapping (not just the earliest), so multi-stint
  overlaps are not missed; the anchor's full participation list keeps both sides visible.
- **Exhibition inspection** of this lens is deferred (production-first).
- Later lenses (lineage C2/M8.3, continuity/rupture C3/M8.4, recurrence C4/M8.5,
  pathway C6/M8.6) remain deferred.
