# M8.1 — Revelation Engine (co-presence) — Engineering Report

## 1. Executive verdict

M8.1 is implemented as a complete production-first vertical slice: one additive
migration (a single bounded `SECURITY DEFINER` read model, `reveal_person_cohorts`,
and **nothing else** — no table, no column, no RLS change, no write path), a new
`src/features/revelation/` module (types/read/parse/derive/copy) reusing the M7
`ProjectedNode` and the shared temporal/provenance kernels, four presentational
components, inline integration on the Scientific Biography, and pgTAP/Vitest/
Playwright coverage plus documentation (ADR-0018, the M8.1 engine doc, and
roadmap/IA/journey/README/ADR-index updates). It is the first slice of M8 —
**Knowledge Revelation** — and it establishes the revelation kernel the remaining
sub-milestones (M8.2–M8.6) reuse.

The revelation composes several `participations` Assertions into the **documented
cohorts** a person belonged to (other people documented at the same institution
during an **overlapping** documented period), each decomposable back to its
participation record. It is deterministic, read-only, provenance-preserving, and
temporally honest; it infers, ranks, recommends, and interprets nothing.

**Validation status.** The pure-logic layers (parse, derive, copy) were executed
and pass here (19/19). A post-implementation verification audit (§10) additionally
confirmed, by reading the real prior migrations and the reused primitives, that
every database column, TypeScript import, UI prop contract, and e2e helper
signature the slice depends on matches the actual M1–M7 code — the failure modes
that would otherwise only surface on the Mac. The database, full type-check, lint,
build, and end-to-end layers themselves require the Mac's Docker-backed Supabase
and the project's native `node_modules`, which are not reachable from the cloud
session (the same constraint recorded for M6/M7). The exact Mac validation sequence
is in §6; **M8.1 is certified complete only after that sequence is green on the
Mac.**

## 3. Constitutional audit (M8 Specification §9.1 invariants)

Each invariant, how it is enforced, and where it is tested:

- **Creates no assertion / read-only.** The migration adds a function only — no
  table, no `INSERT`, no write grant. Composition is recomputed each read.
  *pgTAP:* the function is the sole object; *audit:* `git diff` shows no schema
  table/column/RLS change.
- **No inference.** Co-presence requires a shared institution **and** a temporal
  overlap. *pgTAP:* a co-participant with a non-overlapping period is NOT a member;
  an **undated** co-participant is NOT a member; a person at a **different**
  institution never forms a cohort; every member is justified **only** by a
  `participations` source (co-presence is never promoted to a relationship).
- **No metric / ranking.** No centrality, count-as-importance, or score. Ordering
  is neutral (institution name, then member display_name). *pgTAP:* member order
  is by display_name; *Vitest:* copy carries no metric/ranking/similarity/
  recommendation vocabulary.
- **Deterministic.** Pure function of the record + a fixed rule. *pgTAP:*
  `reveal_person_cohorts(p1) = reveal_person_cohorts(p1)`.
- **Decomposable / provenance-first.** Every member carries its exact
  `participations` `source` id + temporal + provenance; every cohort carries the
  focal anchor(s). *pgTAP:* source.type/id, temporal, capacity, and the focal
  anchor are asserted; provenance renders through the shared `ProvenanceAffordance`.
- **Temporally honest.** Overlap uses stored dates (open end → `infinity`); each
  member/anchor shows its **own** period (no fabricated overlap window); undated
  excluded. *shared kernel* reused unchanged.
- **Fail-closed security.** `SECURITY DEFINER`, `search_path` pinned, `auth.uid()`
  required, revoked from `PUBLIC`, granted to `authenticated`; merged focal →
  null; merged members omitted. *pgTAP:* anon cannot execute; auth required;
  merged/nonexistent handled.
- **Honest incompleteness.** The section states it shows the *documented* cohort,
  not the true one, and that absence is never proof; empty state is dignified.
  *Vitest + Playwright:* limits copy and empty state asserted.
- **No new destination.** Reads inline on `/people/[personId]`; no route, no nav
  entry, no dashboard, no visualization. *Playwright:* the section reads on the
  biography; *audit:* navigation config unchanged.
- **No interpretation.** The pattern is named a structural "documented cohort,"
  never a "community"/"circle"/"group that mattered"; meaning is left to the
  reader and M9. *Vitest:* copy states co-presence is "not a record that they knew
  one another."

## 7. Risks and notes

- **Types regeneration is a hard prerequisite for `typecheck`.** `read.ts` calls
  `supabase.rpc("reveal_person_cohorts", …)`; until `supabase:types` regenerates
  `database.types.ts`, the RPC name is untyped. Sequence handles this.
- **Open-ended overlap.** An unrecorded/open end is treated as open (`infinity`)
  for the overlap test; this is deterministic and shown honestly (each period is
  visible; the limits note states incompleteness). Undated participations are
  excluded, not guessed.
- **Aggregation-harm governance (Spec Limitation C).** M8.1 ships this one
  **curated** lens over already-readable Assertions and inherits M7's posture
  (auth-gated, projects `visible`, fail-closed reads reserve future withholding).
  Free-form reader-composed queries remain deferred until pattern-level consent
  governance exists.
- **Exhibition inspection** of the cohort lens (a `/dev/exhibition` state over the
  seeded world) is intentionally not part of this slice; it is the natural
  "after-production" closing step and is deferred to keep M8.1 scoped. The three
  automated test layers fully exercise the lens deterministically.

## 10. Post-implementation verification audit (this review pass)

After the slice was authored, a full read-only audit re-checked every seam where
the revelation module meets the existing M1–M7 code — the class of defect that a
cloud session cannot catch by running the build, but *can* catch by reading the
real prior migrations and modules the slice binds to. All findings were clean; no
production code was changed.

- **Database column parity (the migration's highest risk).** Every column
  `reveal_person_cohorts` reads was checked against the migration that defines it:
  `participations` (person_id, organization_id, capacity, the eight temporal
  columns, source_type, verification_status, id) against the M6.3 participation
  migration; `participation_capacities` (key, label) against the same;
  `organizations.verification_status` and `.short_name`/`.name` against the M6.5
  institution migration, which adds `verification_status` additively (the base
  M6.3 `organizations` has no such column — a real trap, and it is satisfied);
  `people.display_name`/`.verification_status` (with `merged` a valid status)
  against the identity-foundation migration. No unresolved column.
- **TypeScript imports.** `DATE_PRECISIONS`/`DatePrecision`/`TemporalValue`/
  `formatTemporal` (temporal kernel), `SOURCE_TYPES`/`VERIFICATION_STATUSES`/
  `SourceType`/`VerificationStatus`/`ProvenanceInfo`/`describeProvenance`/
  `ProvenanceDescriptor` (provenance kernel), and `ProjectedNode` (network types)
  all exist with the exact names imported; `NetworkNodeType` includes the
  `"person"`/`"organization"` literals the parser narrows to, so the node
  construction type-checks.
- **Reused UI prop contracts.** `ProvenanceAffordance` (subject, sourceLabel,
  statusLabel, optional projectedFrom), `Badge` (`tone` incl. `warning`/`danger`,
  `size` incl. `sm`), `EmptyState` (required title, optional description), and the
  `TemporalDescriptor` (label, certaintyNote) / `ProvenanceDescriptor` (sourceLabel,
  statusLabel) shapes all match how the components call them.
- **pgTAP fixture parity.** `plan(27)` matches the 27 assertions; every fixture
  insert supplies each NOT-NULL-without-default column of `people`
  (given_name, family_name, display_name, source_type), `organizations`, and
  `participations`.
- **e2e helper signatures.** `registerAndConfirm`, `createBiographyPerson`
  (→ {id, displayName, url}), `createInstitution({name, shortName})`
  (→ {id, name, url}), `addParticipation(personId, orgId, {capacity, startDate})`,
  and the accessibility/page-quality helpers all exist with the signatures and
  return shapes the spec uses.
- **Pure-logic re-run.** The three Vitest suites were re-executed against
  freshly-synced copies of the authoritative revelation module and the real shared/

- **Git scope (read-only).** `HEAD` is unchanged (`fb1797d`, Production Experience
