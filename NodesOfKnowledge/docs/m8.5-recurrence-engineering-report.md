## 2. Exact scope implemented

C4 documented recurrence, **single-entity repetition** (ratified), on the person
and institution surfaces. Person: repeated role at an institution, repeated
same-kind events, repeated same-kind contributions. Institution: repeated
same-kind events and contributions (participations excluded — M8.4 continuity).

## 3. Historical question answered

"What phenomena does the record document as having occurred repeatedly for this
person / this institution — and how many documented times, in what order?"

## 4. Deterministic rule

Group the focal entity's own explicit assertions by a structural recurrence key
(organization+capacity; event_kind; contribution_kind), reveal each group with
**≥ 2** distinct occurrences, carrying a plain count and the occurrences in time
order (undated last). Neutral order (category, then label, then a stable key) —
never by count. Each occurrence decomposes to its canonical row; a role group
anchors its institution as a ProjectedNode; contribution/event occurrences carry
their own node.

## 5. Canonical source assertions

`participations` + `participation_capacities` + `organizations`; `person_events`/
`organization_events` + `events` + `event_kinds`; `person_contributions`/
`organization_contributions` + `contributions` + `contribution_kinds`. No new
table, no write.

## 7. Database / security audit

Two additive functions; no table/column/RLS/write. `SECURITY DEFINER`,
`search_path` pinned to `public, pg_temp`, `auth.uid()` required in-body, revoked
from `PUBLIC`, granted to `authenticated`. Merged focal person → null;
nonexistent focal → null. Bounded and deterministic (GROUP BY + COUNT over
canonical rows; distinct-row de-dup for the link tables). Every referenced column
was verified against the M6.2/M6.3/M6.5/M8 migrations during scope determination.

## 8. Projection / parser contract audit

Every projected node is emitted in the canonical `ProjectedNode` shape; pgTAP
locks it (focal node, a role anchor, an event node, and a contribution node
assert `type`). The parser (`parse-recurrence.ts`) reuses the shared primitives
via `parseAnyNode`, is fail-closed (drops a malformed occurrence; drops a group
that falls below two decomposable occurrences; requires a role group's
organization anchor; a present-but-malformed node fails its occurrence), and — a
recurrence-specific honesty rule — sets the reported `count` to the number of
**surviving** occurrences, so a count never exceeds what a reader can decompose.

## 9. The shared node parser generalization (no duplication)

M8.5 projects contribution and event nodes, which the shared `parseNode`
previously rejected (person/organization only). Rather than duplicate a node
parser, `parse-shared` gained `parseAnyNode` (all four `NetworkNodeType`s) and
`parseNode` now **delegates** to it and restricts to person/organization. M8.1–
M8.4 callers keep their exact prior contract (they also re-check node type
downstream), and the M8.1–M8.4 Vitest suites pass unchanged (87/87 incl. the
prior 71), confirming the refactor is non-breaking.

## 10. Constitutional audit (M8 §9.1) and the "not similarity" guarantee

Read-only (two functions); **no similarity, clustering, pattern mining,
embedding, prediction, or inference** — a recurrence is a GROUP BY + COUNT over
identical explicit key values, computable and checkable by a reader (Spec §3
entailed-relation test); **count, never metric** (Spec §4: neutral order proven
by a count-2 group preceding a count-3 group; the count never ranks or reads as
importance/activity/standing — copy unit-tested to exclude that vocabulary);
**≥ 2 rule** (a single occurrence is never recurrence); decomposable (every
occurrence → its canonical row; institution/contribution doorways); temporally
honest (own dates; undated counts and sorts last; nothing back-filled);
fail-closed security; honest incompleteness (limits + empty state); no new
destination (inline; nav unchanged); no interpretation (structural naming; meaning
left to the reader and M9).

## 11. Rejected alternatives

- **Dyadic co-appearance count (Spec §3.5 literal).** Rejected for this milestone
  in favour of the mission's single-entity reading (ratified by the owner);
  retained as a deferred sibling.
- **Institution participation-recurrence.** Rejected to avoid a duplicative
  reading of M8.4 continuity's per-capacity coverage; institution recurrence
  composes over events and contributions only.
- **Ordering groups by count (a "most-repeated first" list).** Rejected as a
  metric/ranking (Spec §4); order is neutral (category, label, key).
- **Excluding undated occurrences (as M8.4 does for coverage).** Rejected: an
  undated occurrence is still a documented occurrence and counts toward
  recurrence; it is shown last, marked unknown. (This is a deliberate, documented
  difference from M8.4, whose coverage genuinely needs dates.)
- **A dedicated node parser for M8.5.** Rejected as duplication; generalized the
  shared parser instead (§9).

## 13. Defects found and fixed

One, caught in self-review before delivery: an initial copy draft used the word
"importance" in its count-not-metric disclaimer while the banned-vocabulary test
bans "importance" — a self-contradiction. Fixed by rewording the disclaimer to
"not a measure of activity or standing" (and "activity, standing, or weight"),
keeping the evaluative vocabulary banned. No production logic defect otherwise.

## 14. Validation strategy

Three layers, each targeting a distinct risk: pgTAP proves the SQL composition,
the ≥ 2 rule, neutral (non-count) ordering, undated-counts-last, the ProjectedNode
contract, and the participation exclusion; Vitest proves the parser's fail-closed
dropping and count honesty, the derive absence handling and order preservation,
and the copy's count-not-metric neutrality; Playwright proves the two surfaces
read inline, counted, with doorways and honest limits/absence, plus a11y/responsive
quality. The authoring environment runs the pure-logic layer and, via the device
bridge, the JS-only typecheck and lint; the DB/build/e2e layers run on the Mac.

## 15. Limitations

Recurrence is by structural key only (same capacity+org, same event kind, same
contribution kind); a phenomenon documented under two different vocabulary keys
reads as two things (faithful to the record, not merged). The count is of
distinct records, so duplicate records of one real occurrence each count
(stated in the limits). Event occurrences have no reading page (title only, no
doorway). Institution recurrence excludes participations by design (§2, §11).
Dyadic co-appearance recurrence is deferred.
