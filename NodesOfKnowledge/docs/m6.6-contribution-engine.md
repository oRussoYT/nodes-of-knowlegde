# M6.6 — Contribution Engine

Status: Implemented (pending local validation).

The sixth constitutional engine of Nodes of Knowledge. It makes visible what
people, institutions, communities, and knowledge traditions made possible — and
how we know — as a first-class historical object, without fabricating credit,
extracting knowledge, flattening collective action, or turning history into
metrics. See `docs/decisions/0016-contribution-engine.md` (ADR) and
`docs/m6.6-contribution-engine-engineering-report.md` (the definitive
engineering report, including the Benchmarking Synthesis and constitutional
audit).

## What a Contribution is

A Contribution is a historically situated, provenance-bearing account of
something an actor helped bring into being, sustain, transform, preserve,
understand, transmit, or make possible. It is not a publication, an authorship
credit, a CV line, an employment duty, a Participation, a Relationship, an
Event, an institutional output, a dataset, a citation count, an impact score, a
grant, a project milestone, or a claim of importance. It is never inferred from
any of these; each attribution is its own assertion with its own provenance.

## Database (one additive migration)

`supabase/migrations/20260808090000_add_contribution_engine.sql` adds, all
deny-by-default (RLS on, no client policy; table writes granted only to
`service_role`; reads only through SECURITY DEFINER functions):

- `contribution_kinds` — data-backed vocabulary of the *kind* of historical
  object contributed (28 seeded, Node-neutral). Not a publication/authorship
  taxonomy; "mentorship", "funding", and "hosting" are deliberately absent.
- `contribution_capacities` — data-backed vocabulary of the *capacity* in which
  a contributor helped (18 seeded). A different axis from kind. Funding and
  institutional hosting are capacities, never kinds and never ownership.
- `contributions` — the canonical record: `title`, `contribution_kind`,
  `description`, the shared M6.2 Many-Clocks temporal model, a safe-granularity
  `place`, and its own `source_type` / `verification_status`. No ranking, score,
  reach, impact, or count. No contribution "status".
- `person_contributions` / `organization_contributions` — explicit, typed
  attributions, each carrying a `capacity`, an optional `attribution_note`, a
  non-prestige `sort_order`, and its own provenance. `unique(contribution_id,
  actor_id, capacity)`. Not polymorphic.
- `contribution_narrative` — curated interpretation in facets (`overview` /
  `context` / `significance` / `legacy`), one per facet, each with provenance,
  `updated_at` trigger. Separate from the assertion.
- `contribution_events` — projects canonical M6.2 Events onto a contribution
  with no duplication (`unique(contribution_id, event_id)`; mirrors
  `person_events` / `organization_events`). Relation-type vocabulary deferred.

Read model (bounded SECURITY DEFINER, `search_path` pinned, `auth.uid()`
required, EXECUTE revoked from PUBLIC / granted to `authenticated`), composed at
each page:

- `get_contribution(uuid)` — identity + kind + narrative facets + person and
  organization attributions (each with capacity + its own provenance). Merged
  people omitted; merged/historical organizations kept. Null only for a
  nonexistent id.
- `get_contribution_timeline(uuid)` — projected Events, same shape as
  `get_person_timeline` / `get_organization_timeline`.
- `get_person_contributions(uuid)` / `get_organization_contributions(uuid)` —
  the same canonical attributions projected onto a person and an institution
  (the actor's capacity + attribution provenance + the contribution's identity),
  ordered by the contribution's time (undated last). Null for a nonexistent (or
  merged, for a person) subject; empty array when none.

## Application (server-first)

`src/features/contribution/`:

- `types.ts` — domain types (Contribution, attributions, projection documents),
  reusing the shared temporal/provenance kernels.
- `copy.ts` — calm, historical, Node-neutral copy (no ranking/impact/achievement
  language; honest absence; unit-tested).
- `parse.ts` — defensive, fail-closed parsers (drop malformed sub-records; keep
  the rest).
- `derive.ts` — pure presentation: temporal scope via the shared kernel,
  narrative-facet lookup, contributor grouping by capacity (equal dignity), and
  the flat chronological projection view.
- `read.ts` — four bounded server reads, each failing closed to null.
- `components/` — `ContributionIdentityHeader`, `ContributionNarrative`,
  `ContributionTemporalScope`, `ContributionAttribution`,
  `ContributionContributors`, `ContributionInstitutionalContext`,
  `ContributionProvenance` (client; provenance in the accessible name, not only
  a tooltip), `ContributionReservedSection`, `ContributionProjectionEntry`,
  `PersonContributions`, `InstitutionContributions`.

Routes / surfaces:

- `/contributions/[contributionId]` — the dedicated Contribution page: identity,
  overview + historical context, contributors (by capacity), institutional
  context, related events (only when present), significance, legacy, and honest
  reserved Records / Consequences surfaces. Node-neutral generic route.
- `/people/[personId]` — the reserved "Scientific contributions" surface is now
  the live `PersonContributions` projection.
- `/institutions/[organizationId]` — the reserved "Scientific contributions"
  surface is now the live `InstitutionContributions` projection.

All three project one canonical set of records, so they are consistent by
construction, never duplicated claims.

## Collective and Indigenous contributions

A contribution requires no individual contributor. A collective whose authors
cannot or should not be isolated is attributed to a community or Indigenous
organization (M6.5 types) or carried in narrative with an honest limitation —
never a fabricated person. The platform records a historical role, never claims
ownership of knowledge or unauthorized community authorization, and never
exposes culturally restricted knowledge. Community-authorization governance is a
documented deferred extension point, not resolved in code.

- pgTAP: `supabase/tests/database/contribution.test.sql` — vocabularies,
  constraints and shared temporal invariants, attribution integrity (FK,
  unique, note, source), narrative facets, event projection without
  duplication, authorization/deny-by-default, projection consistency,

- Vitest: `contribution-copy`, `contribution-parse`, `contribution-derive` —
  Node-neutral copy without ranking/impact language, fail-closed parsing,
  temporal/provenance derivation via the shared kernels, collective-attribution
  boundary, honest empty states.
- Playwright: `tests/e2e/contribution.spec.ts` — the dedicated page,
  contributors and capacities, institutional context, a projected canonical
  event, collective contribution, temporal honesty, the person- and
  institution-page projections and their consistency, no inference from
  participation or affiliation, accessible provenance name, keyboard,
  light/dark, 375px, no overflow / duplicate ids / console errors, and no
  serious/critical axe violations. Fixtures are disposable and parallel-safe
  (`tests/e2e/helpers/contribution.ts`). Targeted `test.slow()` on the heaviest
  fresh-route scans, justified by the proven Turbopack first-hit compilation
  cost (never global timeout inflation).

## Deferred (reserved, not built)

Universal Entity Engine; generalized polymorphic attribution; a
contribution↔event relation vocabulary; Outputs / Historical Records ingestion /
dataset or publication repository / citation graph; effectiveness or impact
scoring; contribution percentages; rankings; AI-generated attribution or
narrative; automated contributor extraction; duplicate resolution; public
editing; a distinct contributor/host/funder/custodian typology beyond capacity;
community-authorization and culturally-restricted-knowledge governance; Node
administration / federation / tenancy; M6.7.
